## راه‌اندازی سریع

```bash
# ۱) نصب وابستگی‌ها (به‌صورت خودکار Prisma Client را می‌سازد)
npm install

# ۲) ساخت فایل محیطی از روی نمونه و تنظیم مقادیر
cp .env.example .env
#   DATABASE_URL و AUTH_SECRET را ویرایش کنید

# ۳) ساخت پایگاه داده (در صورت نیاز)
mysql -u root -p -e "CREATE DATABASE khodroyab CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# ۴) اعمال مهاجرت‌ها
npm run db:migrate

# ۵) درج ادمین توسعه (فقط در محیط غیر production)
npm run db:seed

# ۶) اجرای برنامه
npm run dev        # حالت توسعه  →  http://localhost:3000
# یا
npm run build && npm run start   # حالت production
```

سپس وارد پنل مدیریت شوید: <http://localhost:3000/admin>

**اطلاعات ورود محیط توسعه:**

| فیلد | مقدار |
| --- | --- |
| شماره موبایل | `09117926950` |
| رمز عبور | `123456` |

> ⚠️ این حساب فقط برای توسعه/آزمایش است. پیش از هر استقرار واقعی، رمز را تغییر دهید یا حساب را حذف کنید.

## متغیرهای محیطی

فایل `.env` (از `.env.example` کپی می‌شود):

| متغیر | توضیح | پیش‌فرض |
| --- | --- | --- |
| `DATABASE_URL` | رشته اتصال MySQL، قالب `mysql://USER:PASSWORD@HOST:3306/khodroyab` | — |
| `AUTH_SECRET` | کلید امضای توکن نشست (JWT). باید محرمانه و تصادفی باشد | — |
| `AUTH_SESSION_TTL_SECONDS` | عمر نشست بر حسب ثانیه | `28800` (۸ ساعت) |
| `NODE_ENV` | در production کوکی‌ها `Secure` می‌شوند و seeder توسعه اجرا نمی‌شود | `development` |

تولید `AUTH_SECRET` امن:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

> `.env` در Git نادیده گرفته می‌شود؛ `.env.example` برای مستندسازی نگه داشته شده است.

## پایگاه داده (Prisma + MySQL)

- اسکیما: [`prisma/schema.prisma`](prisma/schema.prisma) — شامل **۱۳ جدول** با نام‌های فیزیکی دقیق:

  `admins`، `users`، `brands`، `car_types`، `cars`، `options`، `option_items`، `user_car_options`، `user_car_images`، `sale_terms`، `user_cars`، `user_car_sale_terms`، `user_car_sale_term_price_histories`، `user_price_table_entries`

- ویژگی‌ها: شناسه‌های `BIGINT UNSIGNED` با `AUTO_INCREMENT`، ستون‌های `created_at` (پیش‌فرض `CURRENT_TIMESTAMP`) و `updated_at` در همه جدول‌ها، کلیدهای خارجی با رفتار `Restrict`، ایندکس روی ستون‌های FK، و enum نوع `OptionType` (`text`، `select`، `checkbox` با پیش‌فرض `text`).
- مهاجرت اولیه: [`prisma/migrations/20261011112247_init/migration.sql`](prisma/migrations/20261011112247_init/migration.sql)
- نکات و ابهامات اسکیما (به‌همراه فرض‌های اتخاذشده) در [`SCHEMA_REVIEW.md`](SCHEMA_REVIEW.md) مستند شده است.

## پنل مدیریت و احراز هویت

### مسیرها

| مسیر | توضیح |
| --- | --- |
| `/admin` | صفحه ورود (فارسی، RTL) — در صورت وجود نشست معتبر به داشبورد هدایت می‌شود |
| `/admin/dashboard` | ناحیه محافظت‌شده؛ فقط چیدمان و پوسته پنل، **منطقه محتوا عمداً خالی است** (پایه توسعه ماژول‌های آینده) |

### جریان احراز هویت

1. ادمین شماره موبایل و رمز را در `/admin` وارد می‌کند.
2. ورودی‌ها با zod اعتبارسنجی و اعداد فارسی/عربی به ASCII نرمال‌سازی می‌شوند.
3. درخواست از نظر Origin و نرخ تلاش بررسی می‌شود.
4. اعتبارنامه با رکورد `admins` در MySQL (رمز با bcrypt) بررسی می‌شود.
5. در صورت موفقیت، یک توکن JWT امضاشده در کوکی `HttpOnly` قرار می‌گیرد و کاربر به داشبورد هدایت می‌شود.

### لایه‌های حفاظتی

- **سرور (مرجع اصلی):** لایه محافظت‌شده در هر درخواست `requireAdmin()` را صدا می‌زند که توکن را رمزگشایی کرده و **وجود ادمین در پایگاه داده** را بررسی می‌کند؛ در صورت نامعتبر بودن به `/admin` هدایت می‌شود.
- **Middleware (لایه کمکی):** فقط در نبودِ کوکی، دسترسی به مسیرهای محافظت‌شده را می‌بندد. تصمیم نهایی درباره اعتبار همیشه سمت سرور گرفته می‌شود.
- **خروجی:** پاک‌سازی کوکی نشست.

> Middleware هرگز تنها مکانیزم مجوزدهی نیست؛ همه بررسی‌های حساس سمت سرور تکرار می‌شوند.

### جداسازی از سایت عمومی

سایت عمومی و پنل مدیریت از هم جدا نگه داشته شده‌اند:

- کلاس `.admin-root` در [`src/app/globals.css`](src/app/globals.css) یک سیستم طراحی مستقل (توکن‌های رنگ/سایه/انیمیشن با پیشوند `admin-`) تعریف می‌کند که به سایت عمومی نشت نمی‌کند.
- نوار ناوبری، فوتر و داک موبایل سایت عمومی در مسیرهای `/admin/*` رندر نمی‌شوند.
- مسیرهای ادمین با `robots: noindex, nofollow` علامت‌گذاری شده‌اند.

## آپلود تصاویر

تصاویر آپلودشده از پنل مدیریت (برندها، خودروها، کاربران، شرایط فروش) در مسیر `UPLOAD_DIR` ذخیره می‌شوند (پیش‌فرض: `public/uploads`) و توسط خود برنامه در آدرس `/uploads/<بخش>/<فایل>` سرو می‌شوند (`src/app/uploads/[...path]/route.ts`).

> **چرا از پوشه `public` به‌تنهایی استفاده نمی‌شود؟** Next.js در حالت production فقط فایل‌هایی را از `public/` سرو می‌کند که در زمان **build** وجود داشته‌اند؛ فایل‌هایی که بعد از deploy آپلود می‌شوند ۴۰۴ می‌دهند. Route Handler این محدودیت را دور می‌زند و اجازه می‌دهد در سرور، `UPLOAD_DIR` را به یک مسیر پایدار خارج از پروژه اشاره دهید تا با هر deploy پاک نشود.

## امنیت

- رمزها با **bcrypt** (cost = ۱۲) هش می‌شوند؛ هرگز متن ساده ذخیره نمی‌شود.
- نشست به‌صورت **JWT امضاشده (HS256)** در کوکی `HttpOnly` + `SameSite=Lax` + `Secure` (در production).
- پیام خطای ورود **عمومی** است (تفکیک «کاربر ناموجود» از «رمز غلط» ممکن نیست) و مقایسه زمان‌ثابت برای جلوگیری از افشای وجود کاربر.
- **محدودسازی نرخ** تلاش ورود: پس از ۵ تلاش ناموفق در ۱۰ دقیقه، به مدت ۱۵ دقیقه قفل می‌شود.
- بررسی **Origin** در Server Action به‌عنوان لایه دفاعی اضافی (علاوه بر بررسی پیش‌فرض Next.js).
- اعتبارسنجی و نرمال‌سازی کامل ورودی با zod.
- نشست پس از انقضا (`exp`) و در صورت حذف ادمین از پایگاه داده بی‌اعتبار می‌شود.

## نکات و محدودیت‌های شناخته‌شده

- **`admins.name` و سایر ستون‌ها:** ساختار دقیقاً مطابق مشخصات فیزیکی خواسته‌شده است (`users.name` از نوع `BIGINT` و `options.type` enum و…). جزئیات و فرض‌ها در `SCHEMA_REVIEW.md`.
- **محدودسازی نرخ در حافظه:** پیاده‌سازی فعلی per-process است و برای استقرار چندنمونه‌ای باید به یک مخزن مشترک (مثل Redis) منتقل شود.
- **هشدار deprecation در Prisma:** کلید `package.json#prisma` برای seed در Prisma 6 پشتیبانی می‌شود اما در Prisma 7 حذف خواهد شد؛ در ارتقا به `prisma.config.ts` منتقل شود.
- **ESLint پیکربندی نشده است:** اسکریپت `lint` وجود دارد اما هنوز فایل پیکربندی ESLint در مخزن نیست؛ اجرای آن به پیکربندی اولیه نیاز دارد.
